WebSocket Auth Flow

1. Client connects:  ws://host:port?token=<jwt> 
2. Server validates: HMAC signature + expiration check
3. Server responds:  { type: "auth", authed: true, role: "admin" } 
4. All messages gated: Unauthenticated clients get  AUTH_REQUIRED  errors
5. Token refresh: Client can send  { type: "refreshToken", token: "..." } 

GUI Features

- Login Modal: Wallet address input + role selector (operator/viewer)
- Sidebar Status: Shows connected address and role when logged in
- Login/Logout Buttons: Toggle based on auth state
- Auto-prompt: Shows login modal if WebSocket rejects connection
- Token Persistence: Stored in  localStorage , survives page reload
- Onboarding Integration:  connectWallet()  also logs in via auth system

How to Use

// bash
# 1. Set auth secret in .env
echo 'FCM_AUTH_SECRET=my-super-secret-key' >> .env
 
# 2. Start the server
npm run live
 
# 3. Open browser → Login modal appears
# Enter wallet address → Click "Connect"
# Token is stored → WebSocket connects with auth
 
# 4. Or disable auth for development
echo 'FCM_AUTH_REQUIRED=false' >> .env
